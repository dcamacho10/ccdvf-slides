Foundation 01 // Sampling & Probability

Temperature Scaling & Determinism

Temperature = 0.0 (Classifier Mode) High Precision

Concentra a probabilidade estritamente nos tokens mais prováveis. Ideal para classificação, extração e tarefas estruturadas.

Label "SPAM": 98.2%
Label "NOT_SPAM": 1.8%
High Temperature = 1.0 (Creative Mode) Spread Distribution

Espalha a distribuição de probabilidade. Aumenta a variedade do texto e formulações, mas reduz a consistência de rótulos.

Label "SPAM": 55.0%
Label "NOT_SPAM": 45.0%
PEGADINHA DE PROVA (CCDV-F EXAM TRICK)

Temperature 0 NÃO garante determinismo absoluto em APIs de LLM! Embora minimize a variação ao concentrar probabilidade, otimizações de hardware (GPU floating point ops) e clusters de inferência distribuída ainda podem gerar pequenas variações ocasionais. Nunca responda na prova que `temp=0` traz garantia determinística de 100%.

Foundation 02 // Prompting Strategy

Zero-Shot vs. Multi-Shot Structural Enforcement

Zero-Shot Prompt Instructions Only
"Extract user data. Respond strictly in JSON format with keys: name, email, role."

Sintoma: O modelo frequentemente inclui markdown extra (` ```json `) ou comentários explicativos antes do JSON, quebrando parsers estritos.

Multi-Shot (2-3 Examples) Structure Lock
// User provides 2-3 input/output pairs
Input: "John (Admin) - j@cyber.com"
Output: {"name":"John", "email":"j@cyber.com", "role":"Admin"}

Solução: Exemplos práticos demonstram o padrão exato de saída. É a técnica mais eficaz para forçar formatação rígida.

Trade-off & Mito de Treinamento da Prova:

• Não há re-treinamento: Multi-shot NÃO re-treina o modelo de forma permanente. Cada chamada envia os exemplos novamente na janela de contexto.
• Custo de Token: O custo por chamada aumenta na proporção dos exemplos enviados. Adicione apenas a quantidade mínima necessária (2-3 exemplos).

Foundation 03 // Request Architecture

Choosing the Right Request Shape

Pattern Latency Target Cost / Rate Limit Best Fit Scenario
Synchronous API Immediate response required Standard cost / Strict Rate Limits Real-time user actions, single queries
Streaming API Low Time-To-First-Token (TTFT) Standard cost / Real-time UI Interactive chats with human-in-the-loop
Message Batches API Asynchronous (up to 24h) 50% Discount / High Volume Limit 50,000+ overnight docs, offline pipelines
Análise para o Exame CCDV-F:

Em pipelines de batch offline (ex: 50.000 documentos à noite sem usuário aguardando), utilizar um loop síncrono causa estouro de Rate Limits (HTTP 429) e bloqueia a aplicação. O padrão Streaming é inútil pois nenhum humano está assistindo. A Message Batches API é a arquitetura ideal por oferecer 50% de desconto e evitar gargalos de concorrência.

Foundation 04 // Context Mechanics

Context Window Ceiling & Error Handling

Caso 1: Input Oversized Immediate Error

Se o prompt enviado (histórico + mensagens + contexto) já excede o teto da janela de contexto antes do processamento começar:

HTTP 400: invalid_request_error
(Rejeição imediata pré-geração)
Caso 2: Ceiling Reached Mid-Gen Truncated Output

Se o prompt cabe na entrada, mas a geração atinge o teto no meio da resposta, o modelo retorna o texto gerado até o momento e sinaliza:

stop_reason: "model_context_window_exceeded"

Mission Debrief // CCDV-F Exam Day Checklist

Elite Summary: Do's & Don'ts

DO'S (Práticas Corretas)
  • Use Temperature = 0 para classificadores e rótulos previsíveis, sabendo que diminui mas não zera variações de hardware.
  • Aplique Multi-shot (2-3 exemplos) para garantir estrutura JSON rígida que instruções textuais não conseguiram fixar.
  • Selecione a Message Batches API para jobs offline volumosos (ex: 50k docs) para reduzir custos em 50% e evitar rate limits.
  • Implemente poda e sumarização de histórico em agentes longos para prevenir o erro model_context_window_exceeded.
DON'TS (Pegadinhas do Exame)
  • NÃO assuma que Temperature só altera o tamanho da resposta e que o output é 100% determinístico a temp 0.
  • NÃO confunda multi-shot com re-treinamento permanente do modelo. É apenas in-context learning que consome tokens a cada call.
  • NÃO use loops síncronos ou Streaming para processamento noturno sem interface de usuário ao vivo.
  • NÃO espere que a janela de contexto se expanda automaticamente ou descarte turnos antigos silenciosamente sem tratamento na aplicação.
