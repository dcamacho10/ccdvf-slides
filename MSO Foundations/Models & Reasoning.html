INCIDENT ROOT CAUSE: The gateway committed two classic architectural mistakes:
  1. Sent the legacy parameter budget_tokens to a new generation model.
  2. Kept reasoning mode active on trivial classification and lookup tasks.

Defect #1: Legacy Budget Trap

Deprecated Parameter HTTP 400

On newer Claude models, budget_tokens is NO LONGER accepted and raises an HTTP 400 error. Reasoning depth is calibrated strictly via effort.

Defect #2: Reasoning Misallocation

Latency Inflation & Budget Drain

Reasoning modes provide massive returns on multi-step reasoning, coding, and architecture design, but generate unnecessary overhead when applied to simple extractions.

Independent Control Levers

Model Selection vs. Reasoning Modes

TWO INDEPENDENT LEVERS

Choosing which model tier to run is one distinct decision. Deciding whether the model should execute extended thinking is a separate per-call parameter.

Critical Exam Trap

`budget_tokens` Deprecation & HTTP 400 Trap

HIGH PROBABILITY EXAM QUESTION
WRONG (DEPRECATED)

Legacy Parameter Usage

Passing legacy budget_tokens directly to new-generation Claude models.

// Request Payload (Python API)
response = client.messages.create(
model="claude-sonnet-latest",
max_tokens=4096,
thinking={"type": "enabled", "budget_tokens": 2048}, # ❌ ERROR!
messages=[...]
)
PRODUCTION OUTCOME: Returns immediate HTTP 400 Bad Request! The API halts before dispatching generation.
CORRECT (ADAPTIVE THINKING)

Modern Effort Calibration

Adjust reasoning depth via the effort parameter in adaptive thinking mode.

// Request Payload (Python API)
response = client.messages.create(
model="claude-sonnet-latest",
max_tokens=4096,
thinking={"type": "adaptive"}, output_config={"effort": "high"},
messages=[...]
)
PRODUCTION OUTCOME: Succeeds with optimal reasoning allocation calibrated dynamically by Claude.
EXAM WARNING: Watch out for questions asking how to set thinking limits. If the answer offers `budget_tokens` for current models, it is a distractor trap!

Module 01 Takeaways

Lesson 02 Architectural Summary

STATUS: MISSION RESOLVED
1. Sonnet is the Universal Default

Always begin new implementations with Sonnet. Only downgrade to Haiku if latency/cost budgets demand it, and only upgrade to Opus/Fable when backed by empirical evals.

2. Model Tier & Reasoning are Separate

Never couple model tier with reasoning mode. Model tier is an infrastructure choice; reasoning effort is a per-call parameter adjusted to task complexity.

3. Avoid Deprecated Parameter Traps

Passing budget_tokens on newer models triggers an immediate HTTP 400 error. Always use the modern adaptive thinking effort setting.

4. Evals Drive Architectural Choices

In the CCDV-F exam and production systems, decisions between model tiers and reasoning depths must always be verified through quantitative test suites.
