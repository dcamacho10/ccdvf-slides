Foundation Concept

Tokens: The Atomic Unit of LLMs

Cost & Budget Metric

Claude does not read raw characters or words. Everything (system prompts, history, tool outputs, generated text) is measured and billed in tokens.

Key CCDV-F Exam Rules:

  • Model-Dependent: Characters-per-token ratios vary across model generations and tokenizers. Never rely on hardcoded character rules of thumb!
  • Total Accumulation: Input tokens include: System Prompt + Full History + Tool Definitions + Tool Results + Final Response.
  • Billing Standard: API rate limits and pricing are calculated exclusively per token, not per character or word.
Pro Habit: Always estimate costs and context allocation in tokens during system design.
Memory Allocation

The Context Window: Fixed Budget & Edge Cases

Critical Exam Trap

The context window is a fixed budget holding input and output simultaneously. What happens when you breach it?

Edge Case 1: Input Overflow Before Generation

Request prompt + history is already larger than the maximum window size.

API Behavior: Immediate Request Rejection
Error: Validation Error (HTTP 400 / 422)
Generation Status: 0 Tokens Generated

Result: The call fails outright before the model processes any text.

Edge Case 2: Output Overflow During Generation

Input fits, but the model hits the context limit while generating output.

API Behavior: Stops generation gracefully
Output: Partial response returned so far
stop_reason: "model_context_window_exceeded"

Result: No API error code raised! App must inspect stop_reason.

Mitigation: Long running chat sessions must trim or summarize older history before each call.
Probability & Steering

Sampling Controls & The New Model 400 Trap

Exam Hotspot

LLMs produce probability distributions over possible next tokens. How parameters shape this behavior varies by model generation!

Temperature Probability Distribution

Temperature: 0.2 (Low)
Next Token Probability:
"verified" 85%
"confirmed" 12%
"validated" 3%

Lower temp concentrates probability on top tokens. High temp flattens distribution.

The API 400 Parameter Trap

Newer Claude models do not accept non-default sampling parameters (temperature, top_p, top_k).

  • Passing sampling params to models that do not support them returns a HTTP 400 Error.
  • These models are steered exclusively through prompting (system instructions & examples).
  • Temp 0 Myth: Even where accepted, temperature: 0 does not guarantee 100% identical outputs across calls due to underlying system non-determinism.
Rule of Thumb: Always verify parameter support in the official API reference at build time.
Testing Methodology

Non-Determinism & Modern Evals Strategy

Testing Architecture

Because LLMs sample next tokens, identical inputs produce varied surface phrasing. Brittle text equality assertions will break.

WRONG: Exact String Assertions
// BRITTLE TEST (Fails frequently)
assert response.text ==
  "The status is ACTIVE."

Fails whenever Claude phrases the valid response as "Status: Active" or "Account is active".

CORRECT: Structural & Model-Graded Evals
// ROBUST TEST (Properties & Structure)
assert "status" in response.json()
assert response.json()["status"] in ["ACTIVE"]
// Model-graded judge for semantic meaning

Asserts on invariant structural properties or uses a model-graded judge for subjective meaning.

1. Structural Invariants

JSON schema, regex match, key presence.

2. Programmatic Bounds

Numeric range, array length, non-empty text.

3. Model-Graded Judge

Use Claude to evaluate semantic correctness.

Exam Prep Matrix

CCDV-F Architectural Do's & Don'ts

Quick Checklist

CERTIFIED DO'S (Best Practices)

  • Measure in Tokens: Estimate context budget and pricing using token counters, not character/word heuristics.
  • Inspect stop_reason: Check for model_context_window_exceeded to catch truncated outputs gracefully.
  • Steer via Prompting: Use system prompts and few-shot examples on models that do not accept temperature.
  • Use Model Judges: Test output meaning with model-graded evals instead of rigid string matching.

CERTIFIED DON'TS (Exam Traps)

  • Don't Assume Fixed Chars/Token: Tokenizers vary by model generation.
  • Don't Expect 400 on Output Overflow: Context ceiling during generation returns partial text, not an HTTP error code.
  • Don't Pass Legacy Params Blindly: Passing temperature to unsupported Claude models throws a 400 validation error.
  • Don't Rely on Temp 0 for Determinism: Sampling non-determinism can still produce slight variations.
