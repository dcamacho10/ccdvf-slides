High Frequency Exam Topics

Common Misconceptions (DON'T)

Trap 1: Examples Fine-Tune the Model Weights

Believing few-shot examples alter weights permanently. **Fact:** Examples reside strictly in the ephemeral context window and are billed on **every single call**.

Trap 2: HTTP 400 Bad Request vs Output Truncation

Confusing request prompt overflow (`400 Bad Request` before generation) with output token limit cutoff (`stop_reason: max_tokens`).

Trap 3: Appending Rule Paragraphs Instead of 1 Example

Attempting to fix syntax drift by writing walls of negative rules ("Do not...") rather than providing 1 clear worked One-Shot pair.

Certified Best Practices (DO)

Minimal Prompt Discipline

Provide the smallest prompt and fewest examples necessary to pass your automated evaluation suite (*evals*).

Representative Diversity

In multi-shot prompts, ensure examples cover edge cases and input variations without needlessly inflating prompt tokens.

Model + Mode Synergy

Pair **Claude Haiku + Multi-Shot** for high-volume, low-cost pipelines requiring rigorous structural compliance.

PRO-TIP: On the CCDV-F exam, the correct answer almost always prioritizes token efficiency and maintainable context.

CCDV-F Key Takeaways: Prompting Modes

01

Examples Are Context, Not Weights

Examples in prompts do not update model weights (this is not fine-tuning). They reside entirely in the ephemeral context window and incur token costs on **every single request**.

02

Examples Beat Long Rules

One or two worked demonstration pairs (*One-Shot* or *Two-Shot*) correct syntax, formatting, and structural drift far faster and more reliably than walls of descriptive constraints.

03

Model & Mode Synergy

Pair **Claude Haiku with Multi-Shot** to achieve structural accuracy equivalent to much larger tiers on classification/extraction tasks, dramatically slashing operational bills.
