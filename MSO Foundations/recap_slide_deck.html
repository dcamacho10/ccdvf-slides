RULE 01 OF 05

Tokens: The Fundamental Unit of Input, Output & Cost

Tokenization ≠ Character Counting

What is a Token in Claude?

LLMs process information in tokens (sub-word units). One token is approximately 3.5 to 4 characters in English, but varies significantly across code, whitespace, and non-Latin alphabets.

Input Components: Included in Billing
• System Prompt & Formatting Directives
• Full Message History (all previous turns)
• Tool Definitions (JSON Schemas)
• Tool Execution Results

Think & Budget in Tokens

Never budget your architecture in characters or word counts. Rate limits (TPM) and invoices are calculated exclusively per token.

Exam Fact:

Tokens accumulate across multi-turn sessions. Turn 10 costs significantly more than Turn 1 because all previous history is re-sent on every request!

Formula: Total Cost = (Input Tokens × Input Rate) + (Output Tokens × Output Rate)
Architect Rule: Token awareness is the difference between an affordable agent and a $10,000 surprise.
RULE 02 OF 05

Context Window: Fixed Token Budget & Truncation Mechanics

The Two Faces of Limit Breaches
CASE A: INPUT OVERFLOW Pre-Generation

When total prompt tokens (system + history + tools) exceed the model's context capacity.

HTTP 400 Bad Request
"prompt exceeds max context length"

API Behavior: Request fails immediately. Zero tokens are generated. Zero generation cost incurred.

CASE B: OUTPUT TRUNCATION Mid-Generation

When the response hits max_tokens or the remaining context budget.

HTTP 200 OK
stop_reason: "model_context_window_exceeded" | "max_tokens"

API Behavior: Request succeeds with partial truncated text. Always check `stop_reason` before JSON parsing!

Exam Trap Alert: Input overflow returns HTTP 400; output exhaustion returns HTTP 200 with truncated stop_reason.
RULE 03 OF 05

Sampling Makes Generation Non-Deterministic

Temperature, Evals & CI/CD Testing

The Temperature Control Knob

LLMs generate probability distributions over vocabulary. Sampling selects from this distribution.

Temperature = 0.0:

Greedy sampling. Focuses probability on top tokens. Best for classification and structured schemas.

High Temperature (0.7 - 1.0):

Flattens distribution. Increases variety, but reduces rigid schema predictability.

Why Exact String Unit Tests Fail

Never write assertions like: assert res.text == "YES". GPU floating-point non-determinism means phrasing will vary across runs.

Certified Testing Method:

Use behavioral Evals: validate JSON schemas, test invariant properties, or use an LLM-as-a-judge for semantic evaluation.

Key Principle: Test systems probabilistically and architecturally, never through brittle exact string comparisons.
RULE 04 OF 05

Model Choice & Reasoning Mode are Separate Levers

The Two Independent Dials
HAIKU 3.5 SPEED

Blazing fast & cost-efficient. Ideal for real-time routing, simple extraction, and high-volume multi-shot pipelines.

SONNET 3.5 / 3.7 DEFAULT

The balanced default for production software. Handles complex coding, tool orchestration, and agents.

OPUS 3.5 / FABLE DEEP REASONING

Maximum intellectual frontier depth for difficult synthesis, research analysis, and complex logic.

Selected: Claude Sonnet (Balanced Default)

Always start with Sonnet as your default baseline. Only scale down to Haiku or up to Opus when quantitative evaluation suites prove the necessity.

Composable Lever Philosophy: Model choice is an infrastructure tier; reasoning depth is an adaptive per-call effort setting.
RULE 05 OF 05

API Delivery Protocols & Architecture Modes

Sync vs SSE Stream vs Batches
Protocol Mode Latency Profile Cost Profile Ideal Production Scenario
Synchronous REST Blocks until 100% complete Standard Token Rates Headless jobs, cron microservices
SSE Streaming Near-instant TTFT (chunked) Standard Token Rates User-facing interfaces, interactive chat
Async SDK Client Non-blocking event loop Standard Token Rates FastAPI, Express web services
Message Batches API Asynchronous (up to 24h) 50% Token Discount Bulk document ingestion, overnight evals
Exam Rule: If a human user is waiting, stream it. If running bulk offline tasks, ALWAYS choose the Message Batches API.
