TAKEAWAY #1

Tokens: The Fundamental Unit of Input, Output & Cost

Exam Trap: Words ≠ Tokens
1 Token ≈ 0.75 palavras (Inglês)
WORDS 0
EST. TOKENS 0
INPUT COST $0.0000

Think & Budget in Tokens

The API does not count words, characters, or bytes. Pricing metering, rate limits (TPM - Tokens Per Minute), and maximum context window limits are strictly calculated in Tokens.

CCDV-F EXAM TRAP

Código fonte, JSON estruturado, pontuações e idiomas como Português ou Japonês consomem muito mais tokens por palavra do que texto em inglês comum devido à tokenização por subpalavras.

Key Takeaway: Always calculate token usage on real prompt payloads, including tool schemas and system instructions!
TAKEAWAY #2

Context Window: Fixed Token Budget & Truncation Mechanics

Exam Focus: Error 400 vs Mid-Generation Stop
1. OVERSIZED INPUT PROMPT BEFORE GENERATION

HTTP 400 Bad Request

"type": "invalid_request_error"

"message": "prompt is too long: 205,000 tokens > max 200,000"

A requisição falha antes de qualquer geração começar. Nenhum token de saída é faturado. É responsabilidade da aplicação cliente podar o histórico.

2. MID-GENERATION CEILING DURING GENERATION

HTTP 200 OK (Truncated Output)

"stop_reason": "max_tokens" | "model_context_window_exceeded"

"text": "The result of the query is {...[INCOMPLETE JSON]"

A geração atinge o limite do `max_tokens` ou do contexto mid-stream. O modelo retorna uma resposta truncada e válida até aquele ponto.

DO: Implement prompt pruning, sliding window history, and summarize old turns in multi-turn apps.
DON'T: Assume Claude will automatically trim excess conversation history for you in REST requests.
TAKEAWAY #3

Sampling Makes Generation Non-Deterministic

Testing Strategy: Evals > String Equivalence
Simulador de Temperature & Variabilidade Temp: 0.7
Variância de Saída Simulação (3 chamadas idênticas):
Run 1: "To process the user request, we must validate..."
Run 2: "First, let us verify the user credentials..."
Run 3: "Verification step: Checking payload integrity..."

Por que Unit Tests de String exata falham?

Sampling probabilistic means exact string matches (e.g., `assert output == "OK"`) are inherently fragile. Even at `temperature: 0.0`, minor model tweaks or floating-point nuances can vary wording.

A Solução de Engenharia: Evals

Construa Evals (System Evaluations) baseados em asserções comportamentais: validação de Schema JSON, classificadores LLM-as-a-judge e verificações semânticas em vez de comparações literais de texto.

Exam Rule: Evals are the only reliable way to measure prompt performance and guard against regressions.
TAKEAWAY #4

Model Choice & Reasoning Mode are Separate, Composable Levers

Architecture Rule: Scale Capabilities Moderately
Claude Haiku Fast & Light

Ideal for lightweight tasks, quick classification, and high-volume basic extractions.

Cost: $
Latency: Ultra Fast
Claude Sonnet Balanced Workhorse

Optimal balance of intelligence, coding capability, and operational cost.

Cost: $$
Latency: Moderate
Claude Opus Max Intelligence

Top-tier reasoning for highly complex analysis, deep research, and difficult agentic tasks.

Cost: $$$$
Latency: Higher
Composable Lever Philosophy Rule of Thumb

"Pick the smallest model and simplest reasoning/prompting that meets your eval baseline. Add capability (e.g. switch from Haiku to Sonnet or enable extended thinking) only where the eval explicitly dictates you need it."

TAKEAWAY #5

API Delivery Protocols & Architecture Modes

Latency vs Waiting User
PROTOCOL USER WAITING? PRIMARY USE CASE ADVANTAGE / TRADEOFF
Synchronous REST Yes (Short) Quick programmatic APIs, simple scripts Blocking HTTP call. Subject to timeouts on long generations.
Streaming (SSE) Yes (Interactive) Chat UIs, real-time token streaming Perceived zero latency. Requires handling stream event chunks.
Async / Await Non-blocking UI Web app backend handlers, workflow engines Prevents main thread blocking while awaiting response.
Message Batches API No (Offline) Bulk indexing, overnight evaluation suites 50% Cost Discount + huge throughput limits (asynchronous 24h window).
Exam Rule: If user is waiting, use Stream/Sync. If bulk offline processing, ALWAYS choose Message Batches API.

5 Key Takeaways Summary

  • 1. Tokens: Standard unit for metering input, output, and budget costs.
  • 2. Context Window: Fixed budget. Oversize inputs throw HTTP 400; output max tokens truncate with `stop_reason`.
