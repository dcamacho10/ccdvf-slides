Lesson 04 / Architectural Mechanics

SDK Convenience Layer vs. Underlying REST Substrate

1. RAW HTTP / REST API (The Substrate) HTTP/1.1 or HTTP/2

The true interface to Anthropic services is standard HTTP POST to https://api.anthropic.com/v1/messages.

POST /v1/messages HTTP/1.1
Host: api.anthropic.com
x-api-key: sk-ant-api03-...
anthropic-version: 2023-06-01
content-type: application/json

* Exam Rule: The anthropic-version header is strictly mandatory on all direct REST requests.

2. OFFICIAL SDK (Convenience Layer) Python / TypeScript

Anthropic SDKs are lightweight, strongly typed abstractions over the HTTP REST substrate. They do not alter fundamental model behaviors or constraints.

// What the SDK provides automatically:
✓ Injects anthropic-version header
✓ Reads ANTHROPIC_API_KEY from env
✓ Automatic exponential backoff retries on HTTP 429/5xx
✓ Pydantic / TypeScript type validations

* Core Concept: Choosing SDK vs raw REST changes client ergonomics, never server-side limits.

CCDV-F Concept: The SDK is a thin convenience layer over REST HTTP; both adhere to identical rate limits and error codes.

# Direct instantiation with automatic retries and env key validation
import anthropic
client = anthropic.Anthropic() # Reads ANTHROPIC_API_KEY by default

message = client.messages.create(
model="claude-3-5-sonnet-20241022",
max_tokens=1024,
messages=[{"role": "user", "content": "Diagnose latency bug."}]
)
print(message.content[0].text)
// TypeScript SDK is natively Promise-based (No separate Async client required)
import Anthropic from '@anthropic-ai/sdk';
const anthropic = new Anthropic();

async function main() {
const message = await anthropic.messages.create({
model: 'claude-3-5-sonnet-20241022',
max_tokens: 1024,
messages: [{ role: 'user', content: 'Diagnose latency bug.' }]
});
console.log(message.content[0]);
}
# Direct REST HTTP request requires mandatory anthropic-version header!
curl https://api.anthropic.com/v1/messages \
--header "x-api-key: $ANTHROPIC_API_KEY" \
--header "anthropic-version: 2023-06-01" \
--header "content-type: application/json" \
--data '{
"model": "claude-3-5-sonnet-20241022",
"max_tokens": 1024,
"messages": [{"role": "user", "content": "Diagnose latency bug."}]
}'

Lesson 04 / Throughput & Cost

Async Concurrency vs. Message Batches API

1. ASYNC CONCURRENCY (Real-Time Batching) Low Latency

Uses async event loops (`asyncio` / Promises) to fire multiple parallel requests concurrently.

  • ✓ Immediate turnaround (seconds)
  • ✗ Subject to standard API rate limits (TPM / RPM)
  • ✗ Full standard token pricing applies
Best for: Parallel user queries, multi-agent workflows, real-time tool calls.
2. MESSAGE BATCHES API (Offline Bulk) 50% Cost Discount

Submits up to 10,000 requests per batch for asynchronous offline processing within 24 hours.

  • ✓ **50% Token Cost Discount** vs standard prices
  • ✓ Separate batch rate limits (never blocks interactive users)
  • ! Up to 24-hour turnaround SLA (polling retrieval)
Best for: Overnight evaluation runs, bulk document processing, data classification.

Lesson 04 / Executive Summary

CCDV-F Key Takeaways & Protocol Rules

01
SDK vs REST Parity

The SDK is a thin ergonomics wrapper over HTTP REST. Both hit the exact same endpoints, support the same parameters, and share identical rate limits.

02
Streaming (SSE) Mechanics

Drastically cuts Time-To-First-Token (TTFT) for user interfaces. Delivers real-time delta chunks over persistent HTTP connections.

03
Async SDK Asymmetry

Python requires the dedicated AsyncAnthropic client for event loops. TypeScript is natively Promise-based without a separate class.

04
Message Batches API

Designed for offline bulk processing. Delivers up to 24h turnaround SLA in exchange for **50% token cost reduction** and separate rate limits.
