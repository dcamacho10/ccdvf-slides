Workflows vs Autonomous Agents

Workflow Patterns

Code orchestrates the execution path deterministically via fixed routing or chaining.

  • Prompt Chaining: Step A output feeds into Step B prompt.
  • Routing: Classifier sends input to specialized prompts.
  • Parallelization: Multiple sub-tasks run concurrently.

Predictable latency, lower cost, easiest to evaluate.

Autonomous Agent Loops

The LLM dynamically controls its own control flow and tool selection in a loop until it reaches its objective.

  • LLM inspects tool output and decides next action.
  • Adapts trajectory if a tool returns an error.
  • Requires turn limits & circuit breakers.

Higher flexibility, but requires safety guardrails.

// IMPLEMENTATION PATTERN

The Production Agent Loop Blueprint

# Bulletproof Production Agent Loop
MAX_TURNS = 10
turn_count = 0

while turn_count < MAX_TURNS:
  turn_count += 1
  response = client.messages.create(...)

  # 1. Exit condition: Task complete
  if response.stop_reason == "end_turn":
    return extract_text(response)

  # 2. Tool turn execution
  if response.stop_reason == "tool_use":
    results = execute_tools_parallel(response)
    messages.append({"role": "assistant", "content": response.content})
    messages.append({"role": "user", "content": results})

raise AgentMaxTurnsExceeded("Circuit breaker triggered")
Circuit Breaker (MAX_TURNS):

Without a hard max turn counter, an agent trapped in a hallucination or permission loop will burn tokens until billing limits trigger.

Clean Exit on "end_turn":

When Claude determines all information is gathered, stop_reason returns "end_turn". Return the synthesized response to the user.

// SAFETY & GOVERNANCE

Human-in-the-Loop (HITL) Checkpoints

In production, tools have differing blast radiuses: read-only queries (safe) versus mutating financial or operational state (destructive/irreversible).

Irreversible Actions:
  • Executing refunds or bank transfers
  • Deleting user accounts or databases
  • Sending outbound emails to customers
Approval Gate Pattern:

Pause execution, serialize agent state to Redis/DB, prompt human operator for approval, and resume on callback!

# Placing an Approval Gate
DESTRUCTIVE_TOOLS = {"transfer_funds", "delete_record"}

for block in response.content:
  if block.type == "tool_use" and block.name in DESTRUCTIVE_TOOLS:
    approval_token = save_pending_action(block)
    notify_human_operator(block.name, block.input, approval_token)
    return {
      "status": "WAITING_FOR_HUMAN_APPROVAL",
      "action": block.name
    }

The Three Fatal Agent Loop Traps

1. Missing Max Turns

The loop runs while True: with no hard limit. A cyclic tool error burns tokens infinitely.

2. Ignored Tool Errors

Discarding exceptions or returning empty strings instead of is_error: True causes Claude to repeat the same failed call.

3. Ungated Destructive Tools

Allowing an agent to execute irreversible deletions or money transfers autonomously without human confirmation.

Practice Exam Question

When should an architect implement an autonomous Agent Loop rather than a deterministic Workflow pattern (such as Prompt Chaining or Routing)?
A. When latency and cost predictability are the primary engineering objectives.
B. When the sequence of steps and tools needed to solve the problem cannot be predetermined in advance.
C. When the integration performs simple text extraction with no external APIs.
D. Only when Claude 3.5 Haiku is used.
Correct! Option B: Workflows excel when tasks have fixed, predictable steps. Autonomous agents are required when the problem demands dynamic exploration where the model decides next actions based on intermediate tool outputs.
// CERTIFICATION CHEAT SHEET

Agent Rules for CCDV-F Exam

1. Turn Limits are Mandatory

Always enforce a hard MAX_TURNS circuit breaker to prevent infinite token burn.

2. stop_reason Logic

Exit loop on "end_turn"; execute tools on "tool_use".

3. HITL for Irreversible Actions

Never execute financial, deleting, or public dispatch tools without human approval gates.

4. Workflow vs Agent Tradeoff

Favor deterministic workflows for known paths; reserve autonomous loops for open exploration.
