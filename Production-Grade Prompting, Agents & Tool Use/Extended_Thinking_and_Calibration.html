// API ARCHITECTURE

Extended Thinking: The 3 Strict API Rules

# Enabling Extended Thinking in Messages API
response = client.messages.create(
  model="claude-3-7-sonnet-20250219",
  max_tokens=4096,
  thinking={
    "type": "enabled",
    "budget_tokens": 2048 # >= 1024
  },
  # temperature CANNOT be modified (fixed 1.0)
  messages=[{"role": "user", "content": prompt}]
)
Rule 1: Minimum Budget is 1,024

budget_tokens sets the target ceiling for reasoning tokens. The API rejects any value lower than 1,024 with an HTTP 400 error.

Rule 2: max_tokens MUST Exceed budget_tokens

Output tokens include both thinking AND final answer. Therefore, max_tokens must always be strictly greater than budget_tokens!

Rule 3: Temperature Locked to 1.0

When thinking is enabled, setting temperature to anything other than 1.0 throws an immediate API validation error.

// CRITICAL EXAM TRAP

Multi-Turn Thinking Block Persistence

The #1 Bug Planted in Module 2:

Filtering out thinking blocks when storing the assistant turn: [b for b in blocks if b["type"] != "thinking"] # CRASHES!

The Production Fix:

The Anthropic Messages API requires the assistant message in multi-turn tool loops to include the original thinking blocks unmodified. Stripping them breaks conversational trajectory validation!

# Correct multi-turn agent history preservation:
assistant_content = []
for block in response.content:
  # DO NOT FILTER OUT THINKING BLOCKS!
  if block.type == "thinking":
    assistant_content.append({
      "type": "thinking",
      "thinking": block.thinking,
      "signature": block.signature
    })
  elif block.type == "tool_use":
    assistant_content.append(block)

messages.append({
  "role": "assistant",
  "content": assistant_content
})
// SAFETY & COMPLIANCE

Redacted Thinking (redacted_thinking)

In certain safety evaluations or privacy-sensitive contexts, Anthropic's safety classifier may determine that internal reasoning cannot be displayed to the end developer.

Opaque Token Block:

The response content contains a block with type: "redacted_thinking" containing encrypted cryptographic data.

Client Contract:

Your code must treat redacted_thinking as an opaque pass-through object and include it unchanged in conversational history when calling subsequent turns.

# Shape of a Redacted Thinking Block
{
  "type": "redacted_thinking",
  "data": "EkwBCgIQABIgM..." # Encrypted blob
}

# Handling in stream assembler:
if block.type in ("thinking", "redacted_thinking"):
  # Preserve both unchanged in message history!
  history.append(block)

// COST & LATENCY TRADEOFFS

When NOT to Enable Extended Thinking

Low Latency SLAs

Thinking generates hundreds to thousands of reasoning tokens before the first answer token streams. Unsuited for real-time autocomplete.

High-Volume Classification

Simple classification into 3 fixed labels does not need reasoning. Output constraints and few-shot examples are 10x faster and cheaper.

Budget Constraints

Reasoning tokens count toward billable output tokens. Calibrate the budget rather than maxing it out blindly!

Exam Practice Question

A developer implements an agent that uses Claude 3.7 Sonnet with Extended Thinking enabled. On the second turn of a tool-use conversation, the API returns an HTTP 400 Client Error. What is the most likely cause?
A. The developer set max_tokens higher than budget_tokens.
B. The developer stripped the thinking content blocks from the assistant message before sending turn 2.
C. The developer forgot to pass temperature: 0.0.
D. The developer set budget_tokens to 2048 instead of 512.
Correct! Option B: The Anthropic Messages API strictly enforces that all thinking blocks emitted by Claude must be preserved in the assistant message history for subsequent turns. Stripping them triggers an immediate HTTP 400 error.
