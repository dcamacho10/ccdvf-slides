The Message Batches API: 50% Cost Savings

For non-interactive pipelines (e.g. overnight batch evals, historical ticket labeling, bulk document translation), synchronous API calls waste budget.

50% Discount on All Tokens:

Message Batches cut input and output token prices by exactly 50% compared to standard synchronous calls.

24-Hour SLA (Turnaround):

Batches are processed asynchronously and guaranteed to complete within 24 hours (most finish in minutes to hours).

# Submitting a Message Batch
batch = client.messages.batches.create(
  requests=[
    {
      "custom_id": "request-001",
      "params": {
        "model": "claude-3-5-sonnet-20241022",
        "max_tokens": 1024,
        "messages": [{"role":"user", "content": task_1}]
      }
    },
    {"custom_id": "request-002", "params": {...}}
  ]
)
print(batch.id) # msgbatch_xyz
// ASYNC RETRIEVAL PATTERNS

Polling & Retrieving Batch Results

Because batches execute asynchronously, client applications poll status or listen to webhook events.

Processing Status Lifecycle:

in_progress → canceling → ended.

Individual Result Statuses:

Each request in the batch returns succeeded, errored, canceled, or expired. One failed item does not fail the batch!

# Checking Batch Status & Streaming Results
batch = client.messages.batches.retrieve(batch_id)

if batch.processing_status == "ended":
  for result in client.messages.batches.results(batch_id):
    req_id = result.custom_id
    if result.result.type == "succeeded":
      response = result.result.message
      save_output(req_id, response)
    elif result.result.type == "errored":
      logger.error(f"Request {req_id} failed: {result.result.error}")

// PRODUCTION PITFALLS

The Three Batch & Multimodal Traps

1. Polling Too Aggressively

Polling batches.retrieve() in a tight 1-second loop hits rate limits. Poll with exponential backoff (e.g. every 60s).

2. Massive Base64 Payload Bloat

Base64 encoding expands raw binary files by 33%. For recurring large reference assets, use the Files API.

3. SLA Misalignment

Never use Message Batches for user-facing interactive requests. Batches are strictly for asynchronous non-realtime jobs.
