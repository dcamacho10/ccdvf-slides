// EXAM ESSENTIALS

The 4 Failure Modes & Missing Techniques

Observed Failure Missing Technique Why it Fixes the Issue
Wrong Shape (prose instead of JSON) Output Constraints Forces structural boundaries independent of task content.
Scope Drift / Tone Shift over long turns System Prompt Holds persistent rules across turns despite conversation noise.
Invented Structure (unknown format) Few-shot Examples Shows exact pattern/casing that text instructions fail to pin down.
Edge-Case Breaks on variant inputs Variant Constraint / Example Explicitly closes parsing gaps not exposed in happy-path testing.

// ARCHITECTURE SPECIFICATION

When to Reach for Each Technique

1. System Prompts

Persistent behavioral contract layer. Sets role, scope, context rules, and system constraints across multi-turn sessions.

2. XML Tags

Enforces boundaries between instructions, contexts, and few-shot examples. Prevents Claude from treating content as instructions.

3. Few-Shot Examples

Demonstrates output patterns directly. Crucial for exact casing, date formatting, or custom structural representations.

4. Output Constraints

Controls exact format shape (JSON schema, label sets, stop tokens) independent of message content.

// ANTHROPIC BEST PRACTICES

Stacking vs. Simplifying Prompts

Stack All 4 Techniques When:

  • Handling strict downstream API/database parsers.
  • Complex multi-class routing with high ambiguity.
  • Production pipelines processing untested user inputs.
  • Edge cases requiring structural isolation via XML.

Simplify / Avoid Over-Engineering:

  • Single-pass simple tasks (e.g., "Summarize this paragraph").
  • Don't add JSON output schemas + few-shots for basic text ops.
  • Adding more text without prior diagnosis.
  • Writing massive prompts when 1 explicit XML example suffices.
// API LEVEL ENFORCEMENT

Structured Outputs (Constrained Decoding)

Prompting vs. Constrained Decoding

Prompt instructions are requests. Structured Outputs force constraint at generation time token-by-token via API JSON Schema.

// API Request with JSON Schema "output_config": { "format": { "type": "json_schema", "schema": { ... } } }

Two API Use-Cases

  • JSON Outputs: Constrains final assistant response text (e.g., extracting ticket metadata directly).
  • Strict Tool Use: Sets strict: true on tool definitions to validate input parameters before execution in agentic loops.
// ARCHITECTURAL TRADEOFFS

Costs & Limits of API Structured Outputs

Latency & Cost Impact

  • First Request Latency: Schema compilation adds initial latency. (Compiled grammars are cached 24h).
  • Token Cost: API injects a system prompt describing the schema (billed as input tokens).

Edge Cases & Incompatibilities

  • Refusal / Truncation: stop_reason can be refusal or max_tokens (broken mid-structure). Must still check stop reason!
  • Incompatible with Prefilling: JSON Output Schema cannot be combined with assistant message prefilling.

// CERTIFICATION CHEAT SHEET

Key Takeaways for CCDV-F Exam

Prompting Principles

  • Diagnose the failure type BEFORE adding more prompt text.
  • Stack all 4 techniques for deterministic, parsed production outputs.
  • Use XML tags to isolate dynamic input data from instructions.

API Structured Outputs

  • Constrained decoding happens at generation time token-by-token.
  • Compiling new schemas adds initial call latency (cached 24h).
  • Incompatible with message prefilling; requires stop_reason verification.
