// MISSION BRIEFING • INCIDENT #404-MCP

The Committed Subprocess Crash

APEXCORP INFRASTRUCTURE INCIDENT REPORT

ApexCorp committed a project-scoped .mcp.json configured with a stdio transport launching a local Node.js server with raw production API keys embedded in the JSON.

When cloned by Python engineers, the agent loop crashed on missing npx binaries, while the hardcoded secret was harvested by public repository scanners within 18 minutes.

ERROR: stdio transport spawns a local process on every clone; secrets in .mcp.json violate source control governance.
// .mcp.json (Committed to Git — Critical Flaws) { "mcpServers": { "db-service": { "type": "stdio", "command": "npx", // ❌ Assumes Node/npx is installed on every teammate machine! "args": ["-y", "@apex/db-server"], "env": { "DB_KEY": "sk-prod-live-9923847" // ❌ COMMITTED LIVE SECRET! } } } } // Teammate Terminal Crash: $ claude "check database status" [MCP Server Error] 'npx' executable not found in PATH GitGuardian Alert: High Severity Secret exposed in commit 8d4a9
// ROOT CAUSE ANALYSIS

Transports, Scopes & Secrets

1. Stdio Local Dependency

A stdio server runs as a local subprocess. Every teammate cloning the repo must have the server's runtime (Node, Python, Docker) installed locally.

2. Committed Credentials

.mcp.json at repo root travels with code in version control. Never hardcode live secrets; reference environment variables (e.g. ${DB_KEY}).

3. Unbounded Context Costs

MCP tools return large schema definitions and responses. Without prompt caching breakpoints, every turn repays full input token costs.

// MCP PROTOCOL

The Three Core Primitives

Tools

Executable functions called by Claude to perform actions or side-effects.

Example: query_database(sql), send_slack_message(channel).

Resources

Read-only structured data or files provided to the model as context.

Example: postgres://schema/users, file:///logs/today.log.

Prompts

Pre-packaged prompt templates served dynamically by the server to guide the user.

Example: debug-incident-template.
// TRANSPORT DECISION

stdio vs HTTP / SSE Transports

stdio Transport

• Spawns server as a local subprocess on the same machine.
• Communicates via stdin/stdout streams.
• Pros: Zero network overhead, private to host.
• Cons: Requires local runtime (Node/Python/Go) on every teammate's machine. Cannot be shared remotely.

HTTP / SSE Transport

• Connects to a remotely hosted server over HTTPS/SSE.
• Centralized service maintained by DevOps/Infra team.
• Pros: Zero local runtime dependencies for developers; centralized credentials and monitoring.
• Cons: Requires network connectivity and enterprise OAuth/token authentication.

// COST & LATENCY OPTIMIZATION

Prompt Caching in MCP & API

Cache Lifetime & Thresholds

Large tool definitions and system instructions can be cached at breakpoints to reduce cost by up to 90% and latency by 85%.

Default Lifetime: 5 minutes from last read (resets on each read).
Opt-in Extended: 1 hour lifetime (ttl: "1h" on breakpoint).

⚠ Minimum Token Threshold: 1,024 tokens. Prompts shorter than 1,024 tokens are never cached!

// Setting Cache Breakpoint with 1-hour TTL { "type": "text", "text": "Comprehensive enterprise database schema definitions...", "cache_control": { "type": "ephemeral", "ttl": "1h" // Opt-in 1-hour lifetime for long pauses } } // Token Cost Profile: Cache Write: 1.25x base input token price Cache Read: 0.10x base input token price (90% savings!)
// CREDENTIAL HYGIENE

Never Commit Live Secrets

The Leak Mechanism

Because .mcp.json is committed to version control, any raw token written in the JSON file is immediately broadcast to git history and remote mirrors.

The Compliant Fix

Reference environment variables in .mcp.json. Each developer supplies their own credentials through their local environment or secret manager.

// Compliant .mcp.json Pattern { "mcpServers": { "warehouse": { "type": "http", "url": "https://mcp.internal.apexcorp.com", "headers": { "Authorization": "Bearer ${APEX_MCP_TOKEN}" } } } } // Safe: APEX_MCP_TOKEN injected from environment only!

// CERTIFICATION CHEAT SHEET

Lesson 4 Master Rules for CCDV-F

1. stdio Spawns Locally

stdio launches a subprocess on every clone. Teammates must have local runtimes installed.

2. Never Hardcode Keys in .mcp.json

Use ${ENV_VAR} references. Project-scoped configs travel with git history.

3. Cache TTL: 5m vs 1h

Default TTL is 5 minutes from last read. Opt-in 1-hour (ttl: "1h") for paused workflows.

4. 1,024 Token Threshold

Prompt caching only activates above 1,024 tokens. Short prompts are never cached.
