The Fragile Workflow Failure

APEXCORP WORKFLOW PORTABILITY INCIDENT

A lead architect created an automated database verification skill on their local Mac, which worked smoothly in local Claude Code.

When packaged into a team plugin and deployed across headless CI/CD containers and the Messages API, everything crashed: the skill hardcoded local paths, expected interactive shell inputs, and failed because subagents did not inherit the skill.

ERROR: Local machine assumptions break portability across Claude Code, API, and SDK runtimes.
# Faulty SKILL.md (ApexCorp Local Assumptions) --- name: db-audit description: Run DB compliance audit --- # Implementation: 1. Execute /Users/alice/bin/db-check.sh # ❌ Absolute host path! 2. Prompt user: "Confirm password:" # ❌ Interactive prompt in headless API! 3. Delegate verification to subagent # ❌ Subagent doesn't inherit skill! // Cloud Execution Trace: $ claude-agent-sdk run db-audit FileNotFoundError: /Users/alice/bin/db-check.sh SubagentError: skill 'db-audit' unknown in subagent context
// ROOT CAUSE ANALYSIS

The Three Portability Traps

1. Environment Coupling

Hardcoding absolute filesystem paths, OS-specific binaries, or machine-local dependencies destroys portability across developer platforms and CI runners.

2. Interactive Assumptions

Relying on terminal prompts or interactive TTYs fails immediately when running via the Messages API or Agent SDK in automated pipelines.

3. Subagent Isolation

Subagents launch with clean context. They do not automatically inherit preloaded skills or custom instructions from the main session.

// SPECIFICATION

Authoring Portable Skills: SKILL.md

The Author-Once Principle

A skill is a reusable, task-specific procedure. By conforming to standard YAML frontmatter and self-contained scripts, a single SKILL.md runs across all Claude runtimes.

  • name: Unique snake_case or kebab-case identifier.
  • description: Clear semantic explanation of when Claude should invoke this skill.
  • Relative scripts placed inside scripts/ or helper tools.
# .claude/skills/db-audit/SKILL.md --- name: db-audit description: Run non-destructive database health & schema verification --- ## Execution Steps 1. Execute schema inspection using repository tools: `node ./scripts/check-schema.js` 2. Parse JSON output and report missing foreign keys 3. If errors are found, write findings to `reports/db-audit.json`
// RUNTIME COMPARISON

One Skill Across Three Runtimes

1. Claude Code CLI

Discovered automatically via local filesystem paths (.claude/skills/).

Runs in user terminal session under active permission mode.

2. Messages API

Loaded via beta headers and executed in sandboxed code execution containers.

Headless, non-interactive; must provide explicit tool definitions.

3. Agent SDK

Programmatically mounted using settingSources configuration in code.

Exposes same agent loop as CLI; ideal for server-side workflow pipelines.
// WORKFLOW ABSTRACTION

Custom Commands vs Skills

Custom Commands (.claude/commands/)

Simple markdown prompt templates invoked directly by the user with a slash (e.g. /review-pr).

  • User-triggered shortcuts.
  • Fills the prompt prompt with instructions.
  • Does not include standalone bundled scripts.

Skills (SKILL.md)

Self-contained, model-invoked procedures with schemas, executable scripts, and specialized instructions.

  • Model autonomously invokes based on semantic description.
  • Can bundle supporting tools and code scripts.
  • Portable across CLI, API, and Agent SDK.
// DISTRIBUTION

Plugin Architecture & Bundling

What is a Plugin?

A plugin is a versioned bundle distributed through a marketplace or repository that gives a recipient teammate the exact same tool suite in a single install command.

A complete plugin bundles:
• Skills (procedures & scripts)
• Custom Commands (slash templates)
• Hooks (lifecycle enforcement scripts)
• Subagent definitions & MCP configs
# Plugin Directory Layout apex-compliance-plugin/ ├── plugin.json # Manifest & metadata ├── skills/ │ └── db-audit/ │ └── SKILL.md ├── commands/ │ └── audit.md ├── hooks/ │ └── PreToolUse.sh └── .mcp.json # Bundled server configs
// SUBAGENT HYGIENE

The Clean Slate Rule for Subagents

No Automatic Skill Inheritance

When Claude Code delegates a sub-task to a subagent, the subagent starts in a freshly initialized sandbox.

Key Takeaway: Subagents do not inherit skills loaded into the parent session. If a subagent must run a skill, that skill must be explicitly passed or configured in the subagent definition!

Practice Question: Skill Discovery

Scenario: You authored a database auditing procedure in SKILL.md. You now wish to run this workflow across the Messages API and via the Agent SDK. Which of the following statements correctly describes skill handling in these runtimes?

A. All subagents automatically preload skills defined in the parent session.
B. Skills require local shell TTY access and cannot run in Messages API containers.
C. Claude Code uses filesystem discovery, while the Messages API uses beta headers with execution containers, and Agent SDK mounts skills via settingSources.
D. Skills can only be distributed by registering them on the public npm registry.
Correct! Option C: A portable skill works across runtimes because each environment mounts it using its respective discovery mechanism (filesystem for CLI, container beta headers for Messages API, and settingSources for Agent SDK).
// CERTIFICATION CHEAT SHEET

Lesson 3 Master Rules for CCDV-F

1. Subagents Never Inherit Skills

Subagents start with a clean slate. They do not preload skills from the parent session.

2. Decouple Local Environment

Never hardcode host paths or interactive shell prompts in SKILL.md.

3. Commands vs Skills

Commands are user prompt shortcuts (.claude/commands/); Skills are autonomous agent workflows.

4. Plugins are Bundles

Plugins bundle skills, commands, hooks, and MCP configs for consistent multi-team distribution.
