1. Permission Modes & Human Gates

The Agent Loop & Modes

Loop runs Explore → Plan → Code. plan mode blocks writes and stops at the plan. default prompts for every edit/command. acceptEdits auto-approves workspace edits but gates shell commands. bypassPermissions is restricted to sandboxed CI.

Hierarchy Precedence

managed-settings.json (Enterprise) > .claude/settings.json (Project) > ~/.claude/settings.json (User).

Deterministic Deny Rules

The deny array in settings files operates deterministically at the harness level. Matched rules halt execution immediately, even in bypassPermissions mode.

Human Gate Placement

Mandatory human gates for irreversible operations: writes outside repo, destructive shell commands, and production secrets.

// SYNTHESIS PART 2

2. Durable Project Context

CLAUDE.md vs Scoped Rules

Keep CLAUDE.md under 100 lines for global build/test instructions to prevent context dilution. Place domain-specific guidance in .claude/rules/ scoped by frontmatter path globs.

PreToolUse Exit Code 2

Hooks execute shell commands at lifecycle events. A PreToolUse hook exiting with code 2 deterministically blocks tool calls, returning stderr to Claude as feedback.

Subagent Rule Inheritance

Built-in Explore and Plan subagents deliberately skip CLAUDE.md and git status to stay fast and cheap.

Preserving Project Constraints

For sub-tasks where project rules must be respected, use the general-purpose subagent or a custom subagent explicitly configured with required rules.

// SYNTHESIS PART 3

3. Packaging Workflows & Plugins

Author-Once Portability

A portable SKILL.md runs across Claude Code CLI (filesystem discovery), Messages API (beta container), and Agent SDK (settingSources). Never hardcode host paths or interactive shell prompts.

Subagent Clean Slate Rule

Subagents launch with clean context and do not inherit preloaded skills from the parent session. Skills must be declared explicitly for subagents.

Commands vs Skills

Commands (.claude/commands/) are slash prompt shortcuts for human users. Skills (SKILL.md) are autonomous procedures with executable scripts and tool schemas.

Plugin Bundles

Plugins package skills, commands, hooks, and MCP configs into versioned bundles distributed via marketplaces and deployed through enterprise managed settings.

// SYNTHESIS PART 4

4. MCP Servers, Transports & Caching

The stdio Subprocess Rule

stdio spawns a local process on the user machine. Project-scoped configs in .mcp.json travel with git, so every teammate must have the local runtime installed. Never commit live keys!

HTTP / Remote Transport

Connects to centralized remote servers over HTTPS/SSE with zero developer runtime dependencies.

Prompt Caching in MCP

Default cache lifetime is 5 minutes from last read. Opt-in 1-hour lifetime is available via ttl: "1h" on breakpoints.

1,024 Token Threshold

Caching only applies to requests exceeding 1,024 tokens. Short prompts are never cached even if breakpoints are specified.

// SYNTHESIS PART 5

5. Enterprise Security & Compliance

Authentication Matrix

• Remote User Identity (SaaS): OAuth 2.0 per-user tokens.
• Remote Service Identity (Internal): Environment variables only (never committed in git).

Deterministic Audit Trail

PostToolUse hook streams tool arguments and user identity directly to central SIEM on every tool execution. Model cannot suppress or falsify the log.

managed-settings.json Lock

Administrator deployed; cannot be overridden by user or repo configs. Used for mandatory deny rules and preconfigured company MCP servers.

Regulated Customer Review

Passes SOC2 Type II, HIPAA, and ISO reviews by combining locked managed settings, OAuth identity attribution, and immutable PostToolUse hooks.
