The Compliance Audit Disaster

APEXCORP REGULATORY AUDIT REPORT

During an annual SOC2 Type II compliance audit, auditors requested attribution logs for all automated queries touching protected patient database records.

ApexCorp could not produce an immutable audit trail: all Claude Code sessions connected through a shared static service account with zero user-level identity attribution, and tool calls were never logged outside the model's ephemeral context.

ERROR: Lack of user identity attribution, absence of PostToolUse audit hooks, and uncontrolled local settings overrides.
// Non-Compliant Enterprise Setup: { "mcpServers": { "patient-db": { "url": "https://db.internal/mcp", "headers": { "Authorization": "Bearer MASTER_ADMIN_KEY" // ❌ Zero user attribution! } } } } // Audit Question: Auditor: "Which engineer commanded Claude to query Record #8812?" ApexCorp: "Our logs only show 'MASTER_ADMIN_KEY'. The model summarized it in chat..." AUDIT STATUS: FAILED (SOC2 CC6.1 & HIPAA § 164.312(b))
// ROOT CAUSE ANALYSIS

The Three Enterprise Security Pillars

1. User Identity vs Service

When Claude accesses multi-tenant SaaS or user data, authentication must be via OAuth so the token represents the specific human engineer, not a shared master key.

2. Deterministic Audit Hooks

Never rely on Claude to "log what it did." A PostToolUse hook runs unconditionally at the harness layer, recording tool arguments to an external SIEM.

3. Admin Managed Lockout

Enterprise managed-settings.json guarantees developers cannot weaken security rules or bypass required proxy servers on their local laptops.

// COMPLIANCE TELEMETRY

Immutable Logging via PostToolUse Hook

Why PostToolUse is Mandatory

An LLM might summarize: "I checked the customer records." It does not reliably provide raw timestamps, payload hashes, or exact tool parameters.

A PostToolUse hook executes deterministically on every tool completion: • Cannot be suppressed or skipped by the model.
• Transmits tool name, input arguments, and user identity directly to central logging.
• Satisfies SOC2 immutable audit requirements.
// .claude/settings.json (Enforced Audit Hook) { "hooks": { "PostToolUse": [ { "matcher": "*", "command": "./scripts/audit_logger.sh" } ] } } # ./scripts/audit_logger.sh curl -s -X POST https://audit.apexcorp.internal/v1/events \ -H "Content-Type: application/json" \ -d "{\"user\": \"$USER\", \"tool\": \"$TOOL_NAME\", \"payload\": $TOOL_INPUT, \"time\": \"$(date -u)\"}"
// GOVERNANCE

managed-settings.json: The Lockdown

Enforcing Enterprise Standards

Placed by MDM or configuration management in system directories: /Library/Application Support/Claude/managed-settings.json (macOS) or /etc/claude/managed-settings.json (Linux).

Capabilities:
• Overrides all user and project-level settings.
• Locks default permission modes to default.
• Disables risky CLI override flags.
• Preconfigures company-approved MCP servers.
// /etc/claude/managed-settings.json (Locked by IT) { "defaultMode": "default", "allowModeOverride": false, "deny": [ "curl *evil*", "*.pem", "*.key" ], "mcpServers": { "corp-gateway": { "type": "http", "url": "https://gateway.internal.corp/mcp" } } }
// NETWORK SECURITY

Data Residency & Network Egress

Where Does Data Leave the Boundary?

MCP servers act as bridgeheads. If an MCP server connects to third-party endpoints, sensitive database records can leave the enterprise boundary unencrypted.

Enterprise Mandates:
• MCP servers must run inside internal VPC subnets or localhost.
• PreToolUse hook payload sanitization to redact credit card / SSN patterns before dispatch.
• Enforce TLS 1.3 encryption on all remote MCP connections.

Practice Question: Audit Logging

Scenario: A healthcare compliance auditor mandates an immutable record of every tool call executed by Claude Code, including user identity and exact database parameters. Why must this be implemented using a PostToolUse hook rather than prompting Claude to log its own actions?

A. Claude Code does not support tool use in regulated healthcare environments.
B. A PostToolUse hook executes deterministically at the harness layer for every tool call and cannot be skipped or altered by the model's probabilistic decisions.
C. Prompt instructions are stored in managed-settings.json and therefore cannot access bash scripts.
D. PostToolUse hooks run inside a separate subagent context with elevated admin privileges.
Correct! Option B: Compliance logging requires deterministic execution. A PostToolUse hook fires at the harness level for every single tool call regardless of what the model decides, ensuring an inviolable audit trail.
// CERTIFICATION CHEAT SHEET

Lesson 5 Master Rules for CCDV-F

1. OAuth for User Attribution

SaaS integrations require per-user OAuth tokens so actions map back to individual engineers in audits.

2. PostToolUse Hook for Auditing

Deterministic telemetry: logs tool name, arguments, and user identity directly to SIEM without model bias.

3. managed-settings.json is King

Admin-controlled policy file that cannot be overridden by project repos or developer settings.

4. Zero Secrets in Version Control

Always pass API keys via environment variables (${VAR}) in MCP configurations.
